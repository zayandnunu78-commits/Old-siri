# Build and signing setup

## What is now in the project

The repository now contains `project.yml`, `codemagic.yaml`, and the complete `ClassicAssistant/` Swift source tree. XcodeGen creates `ClassicAssistant.xcodeproj` and a `ClassicAssistant` scheme from `project.yml`; the generated application target uses `com.zay.classicassistant`, iOS 16.0, and iPhone-only targeting suitable for iPhone 8 and newer. The configured marketing version is `1.0` and the build number is `1`. The target also generates the required microphone, speech-recognition, launch-screen, portrait-orientation, and original AppIcon asset configuration.

## Apple Developer setup

1. Enroll in the paid [Apple Developer Program](https://developer.apple.com/programs/). A free Apple ID is sufficient only for limited personal-device development and is not sufficient for TestFlight or App Store distribution.
2. In Apple Developer account **Certificates, Identifiers & Profiles**, register an explicit App ID with bundle ID `com.zay.classicassistant`. It must be an App ID owned by the same Apple Developer team used in Codemagic.
3. In App Store Connect, create an iOS app record using the same bundle ID. Choose the final product name and SKU; the code signing identifier is the bundle ID, not the display name.
4. Create an App Store Connect API key with permission to manage apps or the minimum role that permits Codemagic to fetch signing assets and upload builds. Record the issuer ID, key ID, and download the private `.p8` file once. The private key cannot be downloaded again after leaving Apple's creation screen.

## Codemagic setup

1. Add the repository to Codemagic and set the working directory to the repository root, where `codemagic.yaml` and `project.yml` are located.
2. Under Codemagic **Team settings → Integrations → App Store Connect**, create an integration named `codemagic_api_key`, or change the `integrations.app_store_connect` value in `codemagic.yaml` to the exact integration name you choose.
3. Add the Apple Developer team signing credentials or enable Codemagic's automatic code-signing flow for that App Store Connect integration. Codemagic must be able to create or access an App Store distribution certificate and an App Store provisioning profile for `com.zay.classicassistant`.
4. Start the `ios-classic-assistant` workflow. It installs XcodeGen, runs `xcodegen generate --spec project.yml`, runs `xcode-project use-profiles`, and builds a signed IPA with the `ClassicAssistant` scheme.
5. The first workflow intentionally stops after producing an IPA. Once that signed build succeeds, add a `publishing.app_store_connect` block using the same integration if you want Codemagic to upload it to TestFlight automatically.

## Local Mac verification

On a Mac with Xcode and XcodeGen installed:

```sh
xcodegen generate --spec project.yml
xcodebuild -project ClassicAssistant.xcodeproj \
  -scheme ClassicAssistant \
  -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build
```

For a device/archive build, open `ClassicAssistant.xcodeproj` in Xcode, select the `ClassicAssistant` scheme, select the Apple Developer team under **Signing & Capabilities**, and use **Product → Archive**. Device and App Store archive builds require valid Apple signing assets.

## What cannot be verified in this sandbox

This environment is Linux and does not contain Xcode, the iOS SDK, `xcodebuild`, a simulator, or Apple signing credentials. Therefore it is not possible here to truthfully claim that the Swift sources compile, that an Xcode project was generated by XcodeGen, or that a signed IPA was produced. Codemagic or a Mac must perform the final compilation and signing verification.
